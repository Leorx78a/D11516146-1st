## 👥 <a id="50--100-人的大場運作"></a>50 – 100 人的大場運作

這個規模**不能用小班的方式帶**。一個人繞場解決個別問題行不通,關鍵是**把問題批次化**。

### 人力配置

| 角色 | 人數 | 職責 |
| :--- | :---: | :--- |
| **主講** | 1 | 台上推進度、示範、喊停 |
| **副講 / 廣播** | 1 | 盯提問與現場狀況,把重複問題**收攏後請主講統一回答** |
| **助教** | **每 15 人 1 位**(50 人 → 4 位;100 人 → 7 位) | 巡場、桌邊處理、判斷何時該叫學員改用 solutions |
| **技術支援** | 1 | 只處理網路、投影、Actions 卡住等系統性問題 |

> 📌 **助教的第一守則**:不要幫學員 debug 超過 2 分鐘。
> 超過就請他複製 `solutions/`,先跟上進度。
> **助教的價值在於讓全班同步,不是讓某一個人學會。**

### 座位與求助機制

- **6 – 8 人一桌**,每桌指定一位「桌長」(可從報名資料挑程式經驗較高的人)
- 每人發**紅 / 綠兩張紙卡**:卡住就把紅卡立起來,助教掃過全場就知道去哪
- 桌長先處理同桌問題,處理不了才舉紅卡

> 這比舉手有效得多 —— 舉手會累、會不好意思,紅卡立著不用出聲。

### 網路(最大的單點風險)

100 人同時 clone、跑 Copilot、連 MCP,對場地 Wi-Fi 是很大的負擔。

- [ ] **事前場勘**:確認 AP 數量與同時上線人數上限(台中沃茲、高雄亞灣新創園請個別確認)
- [ ] 確認可連 `github.com`、`api.githubcopilot.com`、`learn.microsoft.com`(有些場地會擋)
- [ ] 準備 **2 – 3 支手機熱點**給連不上的人應急
- [ ] **報到時就請大家先連好網路並開好 VS Code**,不要等到 13:40 才發現連不上

> 🔻 **網路全面崩潰的應變**:改成「講師示範 + 全班用 `solutions/` 推關」。
> 教材每一關都有零額度、零 agent 的完成路徑,**這個備援就是為大場設計的**。

### 報到與環境檢查(大場一定要提前)

| 時間 | 做什麼 |
| :--- | :--- |
| **12:40** | 開放入場。投影 [環境檢查清單](00-setup.md),請大家自行對照 |
| **12:40 – 13:10** | 助教巡場,專門抓「Copilot 沒裝好 / 沒登入 / 看不到 Agent 模式」的人 |
| **13:10** | 正式開始 |

> 💡 **提前 30 分鐘報到是大場成敗的關鍵。** 環境問題若拖到實作段才處理,
> 助教會被卡死在少數幾個人身上,整場節奏就散了。

### 進度同步

- 主螢幕**常駐顯示目前應該在第幾關**(另開一台筆電投影,或做一張計時投影片)
- 每關開始前,主講**唸出該關的推關指令**,讓全班一起 push
- **喊停時間點到了就喊停**,不等落後的人 —— 請他們用 `solutions/` 跟上

### 提問

50 人以上用舉手提問效率很差。建議用線上提問工具收題,副講篩選後交給主講**統一回答**。
爐邊會談也用同一個管道收題。

## 🎤 演講一(13:10 – 13:40,30 分鐘)

| 時間 | 主題 | 重點 |
| :--- | :--- | :--- |
| 13:10 – 13:15 | **開場 + 成品 Demo** | 直接展示做完的 To-Do App,再展示 `/fix-issue` 自動開 PR 的畫面。**先給結果,再講原理** |
| 13:15 – 13:25 | **Agent Mode** | Ask / Plan / Agent 對照表。核心一句話:**你給的是目標,不是步驟** |
| 13:25 – 13:32 | **MCP** | 「AI 的 USB-C」。強調安全:只裝信任來源、授權對話框要看 |
| 13:32 – 13:38 | **Agentic Workflow** | 公式:**規矩 + 劇本 + 手腳**。強調「可版控、可 review、團隊共用」 |
| 13:38 – 13:40 | **環境檢查 + 建 repo** | 帶大家一起按 **Use this template**,順便抓出環境有問題的人 |

### 演講一的三個關鍵訊息

1. **Agent Mode 不是自動完成升級版** —— 它會自己開檔案、跑指令、看結果、自我修正
2. **MCP 讓 AI 走出這台電腦** —— 沒有 MCP,AI 只看得到你的檔案
3. **今天的重點是理解,不是把程式碼打完** —— 卡住就用解答檔,沒有人會落後

## ⌨️ 實作段時間控制(13:40 – 15:40,120 分鐘)

| 掛鐘時間 | 應該在哪 | 落後的話 |
| :--- | :--- | :--- |
| **13:50** | 大家 repo 建好、clone 好、issue 出現 | 環境有問題的人先兩人一組 |
| **14:20** | Step 1 完成(To-Do App 跑起來) | **這關最重要,寧可多花 5 分鐘** |
| **14:40** | Step 2 完成 | 落後就把「四種還原方法」改成只講師示範,學員只做方法一 |
| **15:10** | Step 3 完成(MCP 接上) | **這關也是重點**。GitHub MCP 接不上就只做 Microsoft Learn |
| **15:30** | Step 4 完成 | 落後就直接用 `solutions/step-4/` 複製,講師示範 `/fix-issue` 執行過程 |
| **15:40** | Step 5 完成(徽章 + 完成登記) | **絕對不能砍掉**。寧可犧牲 Step 2,也要留滿這 10 分鐘 |

### ⏰ 三個必須喊停的時間點

- **14:20** — 不管 Step 1 有沒有做完,**喊停,統一用 solutions 補齊**,然後往下走
- **15:10** — Step 3 一定要在這時結束,否則 Step 4 會做不完
- **15:30** — Step 4 強制收尾,**把最後 10 分鐘完整留給 Step 5**

### 🏅 Step 5 是最不能砍的一關

很多講師在時間不夠時會砍掉最後一關 —— **這一場千萬不要**。Step 5 是唯一讓學員把東西帶走的環節:

| 為什麼重要 | 說明 |
| :--- | :--- |
| **徽章靠登記發放** | 主辦方依登記名單發送官方認證徽章,**沒登記就拿不到** |
| **登記表是唯一資料來源** | 完成名單、作品連結、測驗結果、課程回饋全部來自這份表單 |
| **現場填表率決定一切** | 下課才提醒,回收率會掉一半以上 |

**現場做法**:15:30 一到就把登記連結的 **QR code 投影出來**,唸出「填完再走」。
資料用途與匯出方式見 [教學方取得的資訊](instructor-data.md)。

## 🎬 Demo 腳本(講師示範用)

### Step 1 示範重點:讓大家「看見 agent 在做事」

貼上提示詞後,**不要講話,讓大家看 30 秒**。然後才說:

> 「注意看,它先列了一份工作清單,然後一個一個檔案建出來。
> 你剛剛沒有告訴它要建幾個檔案、每個檔案放什麼 —— 是它自己決定的。」

### Step 2 示範重點:讓大家「敢按下去」

刻意做壞的那一步,很多學員會不敢執行。要說:

> 「放心弄壞它,我們等一下會救回來。**這一關的重點就是讓你知道怎麼反悔。**」

Restore Checkpoint 一定要**投影出來讓大家看到按鈕在哪裡**。

### Step 3 示範重點:讓大家「看到工具被呼叫」

執行 Microsoft Learn 查詢時,把 Chat 裡的**工具呼叫區塊點開**:

> 「看到了嗎?它自己決定要用文件搜尋這個工具,自己組了查詢字串。
> 我沒有告訴它要查什麼關鍵字。」

### Step 5 示範重點:讓成果「帶得走」

合併 PR 之後,投影出學員的 GitHub 個人資料頁:

> 「注意看左邊 —— 這個 🦈 徽章是 **GitHub 官方發的**,不是我們自己畫的。
> 它會一直留在你的個人資料上。」

接著打開 GitHub Pages 網址:

> 「這是一個公開網址,任何人都打得開。**它可以直接放進你的履歷。**」

⚠️ **三件事一定要講清楚**,否則學員拿不到徽章:

1. **repo 必須是 Public** —— GitHub Achievements 只計算公開 repo 的活動
2. **PR 要 merge,不是 close** —— 這在 GitHub 上是兩種不同狀態
3. **個人設定要勾選 Show Achievements on my profile**

### Step 4 示範重點:最後的「哇」

`/fix-issue` 執行完之後,**切到瀏覽器打開那個 PR**:

> 「我剛剛只打了一行指令。它讀了 GitHub 上的 issue、改了程式、開了分支、推上去、開了 PR。
> 而這整套流程,是一份**你可以 commit 進 repo、給整個團隊用**的 Markdown 檔案。」

## 🚨 現場常見狀況與處置

| 狀況 | 立即處置 |
| :--- | :--- |
| **有人 issue 沒出現** | Actions 頁籤手動 Run **Step 0**。詳見 [疑難排解](troubleshooting.md#issue-沒有自動出現) |
| **一堆人 push 被拒絕** | 全班喊:「執行 `git pull --rebase` 再 push」。這是最常見的 |
| **有人 Copilot 額度用完** | 請他改用 `solutions/`,並提醒可申請 GitHub Education |
| **現場網路很慢,agent 一直逾時** | 果斷改成**講師示範 + 全班用 solutions 推關**。不要讓大家乾等 |
| **GitHub MCP OAuth 大量失敗** | 只做 Microsoft Learn MCP。Step 4 用「把 issue 內容貼給 agent」的替代做法 |
| **有人卡在某一關** | Actions 手動 Run 對應的 Step workflow 強制跳關 |
| **有人改壞了救不回來** | `solutions/` 覆蓋,或兩分鐘重建一個 repo |

> 💡 **全場通用的一句話**:
> 「卡住超過 5 分鐘就用 solutions,先跟上,回家再研究。今天要帶走的是觀念,不是程式碼。」

## 💸 關於 Copilot 免費版的額度

- 免費版的 chat / agent 使用量**有月額度限制**(程式碼自動補完另計)
- 本教材已把全程 agent 回合壓在 **11 次以內**
- 提示詞刻意寫長寫完整,就是為了**一次到位、少來回**
- **每一關都有 `solutions/` 零額度通關路徑**,額度用完不影響完成度

👉 開場時就講清楚這件事,學員才不會在額度用完時慌張。

## 🔥 爐邊會談(15:50 – 16:20,30 分鐘)

> ## 當 AI 成為團隊成員
> ### 軟體開發的下一個十年

形式:主持人 + 1 – 2 位與談人,對談為主、**不用投影片**。

### 為什麼安排在最後

學員剛親手看過 AI 自己改程式、自己開 PR。**這個當下最適合談「所以未來會變成什麼樣」** ——
全場有了共同的具體經驗,討論不會流於空泛。

### 討論題綱

| # | 題目 | 想帶出什麼 |
| :-: | :--- | :--- |
| 1 | 今天大家看到 AI 自己開了 PR。**再往前三年,開發工作還有哪些部分是人在做?** | 破題,連結剛才的實作體驗 |
| 2 | **當寫程式碼變便宜,工程師的價值往哪裡移動?** | 從「產出」轉向「判斷、架構、驗收」 |
| 3 | Agent 會犯錯。**團隊要怎麼建立信任機制** —— code review 還夠用嗎? | 呼應 Step 2 的還原練習 |
| 4 | **哪些工作值得寫成 agentic workflow,哪些不值得?** | 給可帶走的判斷準則 |
| 5 | 對**剛入行**或**正在轉職**的人,現在最該練的能力是什麼? | 照顧年輕聽眾 |
| 6 | 如果只能給在座一句話帶回公司,會是什麼? | 收尾 |

### 主持提醒

- 留 **5 – 8 分鐘**給現場提問,用線上提問工具收題並投票,不要舉手
- 與談人**事前給題綱**,但現場不要照稿念
- ⏰ 實作段 15:40 一定要結束,15:40 – 15:50 是休息。爐邊會談準時 15:50 開始
- 開場前再提醒一次:**還沒填完成登記表的請趁現在填**(QR code 留在螢幕上)
