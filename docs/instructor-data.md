# 📊 教學方取得的資訊

> 這份文件只給主辦方 / 講師看。說明**辦完一場工作坊,你會拿到哪些資料、怎麼拿、拿來做什麼**。

所有資料都透過**一個入口**收集:學員在 Step 5 填寫的 **[完成登記表](../.github/ISSUE_TEMPLATE/workshop-completion.yml)**(一份 GitHub Issue Form)。
學員大約花 2 分鐘,你就拿到下面全部欄位,而且是**結構化、可直接匯出成 CSV** 的。

---

## 一、資料總覽

### 🎯 A 類:名單與認證(發徽章必需)

| # | 資料 | 取得方式 | 用途 |
| :-: | :--- | :--- | :--- |
| 1 | **完成學員名單**(姓名 / 暱稱) | 登記表必填 | 核發徽章、結業名冊 |
| 2 | **GitHub 帳號** | 登記表必填 | **徽章發到這個帳號**,填錯就發不出去 |

| 4 | **徽章發放同意** | 登記表必勾 | 個資使用的合規依據 |
| 5 | **完成到第幾關** | 登記表必填 | 區分「全部完成」與「部分完成」,決定發不發證 |

### 🌐 B 類:學員作品

| # | 資料 | 取得方式 | 用途 |
| :-: | :--- | :--- | :--- |
| 6 | **作品 repo 網址** | 登記表必填 | 驗收、成果彙整 |
| 7 | **GitHub Pages 作品網址** | 登記表選填 | 成果牆可以直接點開來看 |
| 8 | **公開展示授權** | 登記表選填勾選 | **沒勾就不列入公開成果牆** |
| 9 | **repo 的客觀狀態**(是否公開、PR 數、commit 數、Pages 是否啟用) | 匯出腳本自動抓取 | 驗證完成度,不必相信自我回報 |

### 📈 C 類:課程成效與改進(以下是我建議補充的)

| # | 資料 | 取得方式 | 為什麼值得收 |
| :-: | :--- | :--- | :--- |
| 10 | **每關通關漏斗** | 由第 5 項統計 | 找出**流失最多的那一關**。這是下一場最該改的地方 |
| 11 | **五題測驗逐題答對率** | 登記表 5 個必填題 | 哪一題錯最多 = **哪個觀念沒講清楚**。比整體分數有用得多 |
| 12 | **Copilot 方案分布** | 登記表選填 | 了解學員實際條件,決定要不要事前推 GitHub Education |
| 13 | **額度是否用完** | 登記表選填 | **驗證「免費版可完成」這個對外承諾**。若多數人中途用完,教材要再瘦身 |
| 14 | **卡關點分布**(11 個選項複選) | 登記表選填 | 現場改善的第一手依據,直接對應到要補強的環節 |
| 15 | **學員背景**(角色、程式經驗) | 登記表選填 | 分眾。若非工程師比例高,下一場要調整用語與節奏 |
| 16 | **幫助程度**(1 – 5) | 登記表必填 | 對主管交代成效的主要數字 |
| 17 | **推薦意願** | 登記表選填 | 判斷要不要開下一場、開幾場 |
| 18 | **文字心得與建議** | 登記表選填 | 質化回饋。挑幾則放進成果報告很有說服力 |
| 19 | **徽章達成率**(YOLO / Pull Shark / Pages) | 匯出腳本自動抓取 | 衡量「獎勵機制」本身有沒有效 |
| 20 | **實際耗時 / 真實配速** | 匯出腳本讀 commit 時間戳 | 用真實資料校正下一場的時間配置,而不是憑感覺 |

> 💡 **為什麼把五題測驗放進登記表,而不是讓學員自己對答案?**
> 自我回報「我答對幾題」拿不到逐題資料。放進表單後,你能看到**第 3 題有一半的人選錯**,
> 那就知道「還原機制」這段下次要重講。解析仍然會在練習 issue 裡完整貼給學員。

## 二、怎麼把資料撈出來

### 前置作業

1. 確認 **template repo 的 Issues 功能是開啟的**(Settings → Features → Issues)
2. 安裝並登入 [GitHub CLI](https://cli.github.com/):`gh auth login`

### 匯出

在 template repo 目錄下執行:

```bash
node scripts/export-completions.mjs
```

會產生兩個檔案:

| 檔案 | 內容 |
| :--- | :--- |
| `out/completions.csv` | 每位學員一列,所有登記欄位 + 自動抓取的 repo 狀態。可直接用 Excel 開 |
| `out/SHOWCASE.md` | 學員成果牆(**只包含勾選了公開展示授權的人**) |

也會在終端機印出即時統計:認證人數、各關通關數、逐題答對率、卡關點排行、滿意度平均。

### 分場次統計(六場共用同一個登記 repo)

本系列共六場,全部登記在同一個 repo,用 **label 區分場次**:

| 日期 | 場型 | 城市 | 場地 | 場次 label |
| :--- | :--- | :--- | :--- | :--- |
| **9/19** | 全日 | 台北 | 華南 3F | `2025-09-19-taipei` |
| **10/31** | 半日 | 台中 | 沃茲 | `2025-10-31-taichung` |
| **11/21** | 半日 | 高雄 | 亞灣新創園 | `2025-11-21-kaohsiung` |
| **12/12** | 半日 | 台中 | 沃茲 | `2025-12-12-taichung` |
| **1/9** | 半日 | 高雄 | 亞灣新創園 | `2026-01-09-kaohsiung` |
| **1/23** | 全日 | 台北 | 華南主廳(暫定) | `2026-01-23-taipei` |

**每場預計 50 – 100 人**,六場合計約 300 – 600 人次。

#### 開課前

1. 在登記 repo 建好該場次的 label
2. 把 Step 5 與 `docs/badges.md` 的登記連結改成:
   `...?template=workshop-completion.yml&labels=completion,2025-09-19-taipei`
3. 用這個連結產生 QR code,放進投影片最後一頁

#### 課後匯出

```bash
# 單一場次
node scripts/export-completions.mjs --label 2025-09-19-taipei

# 全系列六場合計
node scripts/export-completions.mjs
```

> 💡 **跨場次比較很有價值**:同一份教材在不同城市、不同場地跑六次,
> 通關漏斗與卡關點的差異會直接告訴你哪些問題是**教材造成的**(每場都一樣),
> 哪些是**現場造成的**(只有某一場特別高,通常是網路或環境)。

## 三、隱私與合規(請務必看)

| 事項 | 做法 |
| :--- | :--- |
| **登記 issue 是公開的** | 表單開頭已明確提醒學員**不要填寫私人資訊**。欄位設計上也刻意不收手機、信箱、身分證號 |
| **測驗答案會公開** | 後面場次的學員看得到前面的作答。若你在意,見下方「想要非公開」 |
| **公開展示需要授權** | 成果牆只收錄**勾選同意**的人。匯出腳本會自動過濾 |
| **徽章發放同意** | 表單設為必勾,作為使用 GitHub 帳號的依據 |
| **資料保存** | 建議統計完成後,把不再需要的登記 issue 關閉或轉為封存 |

### 想要非公開怎麼辦

三個選項,由簡到繁:

1. **把登記用的 repo 設為 Private**,並邀請學員為 collaborator —— 最單純,但學員要接受邀請,現場會多一道手續
2. **另開一個專用的私有登記 repo**,教材 repo 維持公開 —— 推薦。只要改 Step 5 與 `docs/badges.md` 裡的登記連結
3. **改用外部問卷工具**(Google 表單 / Microsoft Forms)—— 資料最私密,但就失去「一鍵匯出 + 自動抓 repo 狀態」的好處

> 🔧 登記連結只出現在兩個地方,要換很快:
> `.github/steps/5-step.md` 與 `docs/badges.md`。

## 四、建議的追蹤節奏

| 時間點 | 做什麼 | 拿到什麼 |
| :--- | :--- | :--- |
| **課程結束當下** | 提醒所有人填登記表(現場填完再走) | 名單、作品、測驗、即時回饋 |
| **當天晚上** | 跑一次匯出腳本 | 完成率、逐題答對率、卡關排行 |
| **隔天** | 在登記 issue 回覆學員,告知徽章進度 | 學員黏著度 |
| **一週內** | 整理成果報告給主管 | 對外交代的數字與案例 |
| **一個月後** | 在登記 issue 統一留言詢問實際導入情形 | **最有說服力的成效證據**:誰真的把它用在工作上 |

> 📌 **現場填表率是關鍵**。下課才提醒,回收率會掉一半以上。
> 50 – 100 人的場子更要把「填登記表」排進 Step 5 的 10 分鐘裡,並在爐邊會談開場前再提醒一次。
> 建議把「填登記表」直接排進 Step 5 的 10 分鐘裡,並在投影片上放大 QR code。
